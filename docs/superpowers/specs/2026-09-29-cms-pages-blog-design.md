# CMS pages and blog (WordPress merge)

**Date:** 2026-09-29
**Status:** Designed, awaiting the open questions at the end
**Repos:** `catlab-events`
**Investigation:** `/mnt/project-files/wordpress-merge/assessment.md` (option A, decisions of 2026-09-29)

## Goal

Move the marketing site `quizfabriek.be` (WordPress: ~9 live Elementor
pages, 36 Gutenberg blog posts) into this Laravel app, so one application
serves `quizfabriek.be` and the ticketing that lives on
`tickets.quizfabriek.be` today, and WordPress plus Elementor Pro can be
retired.

Concretely:

- **Pages** are built by non-developers in the admin panel out of **section
  blocks** (hero, text + image, cards, upcoming events, reviews, call to
  action, rich text, ...). Each block type is one Blade partial; the Blade
  holds design only, every word and image lives in the database as JSON.
- **Blog posts** have one rich-text body each. All 36 WordPress posts are
  imported with their media, and their `/YYYY/MM/DD/slug/` URLs keep working.
- **Multilingual from day one:** every page and post has per-locale
  translations (own slug, title, blocks or body, SEO meta) sharing one id.
  Dutch stays at the root, English and French under `/en/` and `/fr/`.
  A missing translation is a 404, never a Dutch fallback.
- **Multi-tenant:** all content is scoped to the organisation resolved from
  the hostname (`Organisation::getRepresentedOrganisation()`,
  `app/Models/Organisation.php:272`), exactly like events and series.
- **Cutover without losing SEO:** 301s for old URLs, sitemap entries,
  hreflang, the RSS blog block replaced by local posts, `quizfabriek.be`
  added as an `OrganisationDomain`, `tickets.quizfabriek.be` redirected.
- **Secure by construction:** every rich-text field is sanitised on write,
  editing is admin-only behind the existing `auth` + `admin` middleware
  (`app/Http/Kernel.php:939`, `app/Http/Middleware/IsAdmin.php`) plus the
  organisation-admin check the newer admin controllers already do
  (`GuestRegistrationController::getEventInOrganisation()`).

## Non-goals

- Translating the ticketing pages (event, series, order, group views). They
  stay Dutch; only the shared chrome strings that CMS pages also show
  (menu, footer, language switcher, blog labels) go through
  `resources/lang`.
- Porting the `-nieuw` draft pages or `sko_milk`.
- Drag-and-drop or live WYSIWYG page building. The editor is a server-side
  form with a block list (add, remove, move up/down) and a rich-text editor
  inside text fields. Good enough for nine pages that change a few times a
  year.
- Comments, categories, tags, authors, RSS consumption. (Producing a feed is
  optional; see open questions.)
- A generic page cache. The site is small; queries are cheap.
- Replacing the theme. Blocks are styled with the existing Bootstrap 4 theme
  (`resources/assets/sass/style.css`) plus one new `cms.scss`.

## What exists today (grounding)

- **No CMS at all.** Public content is events, series, venues, competitions,
  plus fixed views (`resources/views/blocks/about.blade.php` holds
  hard-coded Quizfabriek copy; `HomeController@press` and `sponsors.blade.php`
  are one-offs).
- **Homepage** `/` is `EventController@index` (`app/Http/Controllers/EventController.php:81`),
  which renders the series page of the next upcoming event.
- **Admin CRUD** is generated by Charon: `BaseAdminController` wraps
  `CatLab\CharonFrontend\Controllers\FrontCrudController`
  (`app/Http/Controllers/Admin/BaseAdminController.php`), each controller
  points to an API `ResourceController` and a `ResourceDefinition`
  (`app/Http/Api/V1/ResourceDefinitions/SeriesResourceDefinition.php`), and
  routes are registered with `::routes('series', 'Admin\SeriesController', 'series')`
  from `routes/web.php:70-81`. Non-CRUD admin screens are plain controllers
  and Blade forms under `layouts/admin`
  (`Admin\GuestRegistrationController`, `Admin\RefundController`,
  `Admin\WaitingListController`).
- **Uploads** go through `\CentralStorage::store($file)` (external central
  storage service, `Admin\AssetController@upload`), producing rows in the
  local `assets` table (`CatLab\CentralStorage\Client\Models\Asset`) whose
  `getUrl(['width' => ...])` returns a resized public URL. Series and
  organisations reference assets by `*_id` foreign keys.
- **Blog block** `resources/views/layouts/blocks/blog.blade.php` reads
  `organisation()->blog_rss_url` through `\Feeds::make()`, included from
  `resources/views/series/view.blade.php:334`. **`Feeds` does not exist in
  this codebase** (no package in `composer.json`, no alias in
  `config/app.php`), so the block only works because `blog_rss_url` is
  `NULL`; if it were set the homepage would 500. It gets replaced either way.
- **Sitemap** `SitemapController` builds an array of urls, cached for an
  hour under one global key, rendered by `resources/views/sitemap.blade.php`.
- **Locale** is `nl_BE.utf8` (`config/app.php:97`) with fallback `nl`;
  lang files exist for `nl`, `en`, `fr` (`livestreams.php`,
  `organisation.php`, ...). Views are almost entirely hard-coded Dutch.
- **Domains:** `ValidDomain` middleware (`app/Http/Middleware/ValidDomain.php`)
  is meant to redirect to `VALID_DOMAINS[0]`, but reads an undefined `$hos`
  variable (line 761), so it never redirects. It cannot be used for the
  `tickets.quizfabriek.be → quizfabriek.be` redirect as-is, and fixing it
  naively would redirect every other organisation's domain to the first
  valid domain. This design adds a per-organisation canonical domain
  instead (see Cutover).
- **Tests:** integration suite in `tests/Integration` (`RefreshDatabase`
  on MySQL 8, `bin/integration-tests.sh`, CI in
  `.github/workflows/tests.yml`), fixtures in
  `tests/Integration/Concerns/CreatesEventFixtures.php`, PHPUnit 11.
- **Deploy** runs `artisan route:cache` (`build/upgrade.sh`), so all new
  routes must be cacheable (controller strings, no closures).

### `organisations.home_page_id`

Decided: the homepage is chosen explicitly per organisation. New nullable
column `organisations.home_page_id` (FK `pages.id`, `nullOnDelete`). When it
is set and the page has a published translation in the requested locale,
`/` (or `/en`, `/fr`) renders that translation; the page's own path 301s to
the locale root so there is one URL per home. When it is `NULL`, `/` keeps
the existing `EventController@index` behaviour and `/en`, `/fr` 404.
Deleting the page clears the column. The admin picks it from a "Startpagina"
select on the organisation (writeable field in
`OrganisationResourceDefinition`) and via a "Stel in als startpagina" action
on the pages index.

### `organisation_domains.is_canonical`

One new nullable boolean on the existing table (`2020_04_22_173612_add_organisation_domains_table.php`).
When an organisation has a canonical domain, requests for any of its
other domains are 301'd there (see Cutover). For Quizfabriek the canonical
domain is `www.quizfabriek.be` (decided). Apart from this and
`organisations.home_page_id`, no schema change to existing tables. `organisations.blog_url` / `blog_rss_url` stay but stop
being read once posts exist.

## Routing and precedence

### Locale prefix

`config/cms.php`:

```php
return [
    'locales' => ['nl', 'en', 'fr'],
    'default_locale' => 'nl',        // served at the root, never prefixed
    'reserved_slugs' => [ ... ],     // see below
    'blocks' => [ ... ],             // block type registry
    'posts_per_page' => 12,
];
```

The CMS routes are registered **once at the root and once under
`{locale}`**, from a single closure, so there is exactly one list of routes
to maintain:

```php
// routes/web.php, LAST, after ReferenceController::routes()
$cms = function () {
    Route::get('blog', 'PageController@blogIndex');
    Route::get('{year}/{month}/{day}/{slug}', 'PostController@show')
        ->where(['year' => '\d{4}', 'month' => '\d{2}', 'day' => '\d{2}', 'slug' => '[a-z0-9\-]+']);
    Route::get('{path}', 'PageController@show')->where('path', '[a-z0-9\-/]+');
};

Route::middleware('cms.locale')->group($cms);                         // nl at the root
Route::prefix('{locale}')->where(['locale' => 'en|fr'])
    ->middleware('cms.locale')->group(function () use ($cms) {
        Route::get('/', 'PageController@home');
        $cms();
    });
```

(The `where('locale', 'en|fr')` is generated from `config('cms.locales')`
minus the default; hard-coded here for readability.)

The Dutch home page is not a new route: `EventController@index` (the
existing `/`) first asks `PageController::homeFor(organisation(), 'nl')`,
which reads `organisations.home_page_id`. If it is set and that page has a
published Dutch translation, the translation is rendered; otherwise the
existing series/calendar behaviour runs. Organisations that never set a
home page keep their current homepage untouched. `PageController@show`
301s a request for the home page's own path to the locale root.

### Precedence

Laravel matches routes in registration order, so:

1. Everything in `routes/web.php` today wins over CMS pages because the CMS
   group is registered last. `/events`, `/e/…`, `/s/…`, `/orders`,
   `/groups`, `/admin`, `/login`, `/archive`, `/calendar`, `/competitions`,
   `/author/…`, `/venues/…`, `/organisations/…`, `/invitations/…`,
   `/livestreams`, `/status`, `/sitemap.xml`, `/docs`, `/documents/…`,
   `/press`, `/donate`, `/doneer`, `/home` are all unreachable as page
   paths.
2. Inside the CMS group the dated post route is registered before the page
   catch-all. A page path of four numeric segments is impossible anyway
   (`reserved_slugs` plus the slug format).
3. The page catch-all requires `[a-z0-9\-/]+`, so anything with a dot
   (`wp-login.php`, `feed.xml`), uppercase or query-only URLs falls through
   to `Route::fallback('RedirectController@fallback')`, which consults
   `cms_redirects` and otherwise 404s.
4. Trailing slashes need no handling: `Illuminate\Routing\Matching\UriValidator`
   rtrims the path before matching, so `/over-ons/` (the WordPress form)
   serves the page and the `<link rel="canonical">` points at `/over-ons`.

`reserved_slugs` (validated when a **top-level** page slug is saved, and
checked by a test that reads the route collection so it cannot silently
drift): `admin, api, archive, author, blog, calendar, catlabaccount,
competitions, docs, documents, donate, doneer, e, en, events, fr, groups,
home, invitations, livestreams, login, logout, nl, orders, organisations,
password, press, register, s, sitemap.xml, status, venues, css, js, fonts,
images, storage` plus every top-level segment the test finds in
`Route::getRoutes()`. Child slugs are unconstrained except for the format.

Because `route:cache` runs on deploy, all routes are controller strings
(no closures, the group closure above is fine because it only registers).

### Locale middleware `App\Http\Middleware\SetCmsLocale` (alias `cms.locale`)

- Reads the `locale` route parameter; absent means `config('cms.default_locale')`.
- Rejects anything not in `config('cms.locales')` with 404 (belt and braces,
  the route constraint already does this).
- `app()->setLocale($locale)` and `Carbon::setLocale($locale)`, then
  `$request->route()->forgetParameter('locale')` so controller signatures
  do not receive it.
- Shares `cmsLocale` with the views (`View::share`).

`app.locale` (`nl_BE.utf8`) is untouched: the ticketing routes never pass
through this middleware and keep behaving as today. `resources/lang/nl`
already resolves as the fallback for those.

### Controllers

- `App\Http\Controllers\PageController@show(Request, string $path)`:
  organisation from `organisation()`, locale from `app()->getLocale()`,
  `PageTranslation` by `(organisation_id, locale, path)`. Unpublished or
  missing translation → try `cms_redirects` → 404. `?preview=1` shows an
  unpublished translation to an admin of the organisation (the same check
  as `getEventInOrganisation()`), and adds `<meta name="robots" content="noindex">`.
- `PageController@home` (locale-prefixed root), `PageController@blogIndex`.
- `App\Http\Controllers\PostController@show(year, month, day, slug)`:
  translation by `(organisation_id, locale, slug)`, published; if the date
  segments do not match `published_at` in Europe/Brussels, 301 to the
  canonical URL (so a typo'd or timezone-shifted old link still lands).
- `App\Http\Controllers\RedirectController@fallback`: looks up
  `cms_redirects` for the organisation and `trim($request->path(), '/')`,
  plus `?p=ID` shortlinks resolved through `posts.wp_post_id`; else 404.

## Block system

### Storage format

`page_translations.blocks`:

```json
[
  { "id": "b3f1a9", "type": "hero", "data": { "title": "…", "subtitle": "…", "image_id": 42,
      "buttons": [ { "label": "Bekijk de kalender", "url": "/calendar", "style": "primary" } ] } },
  { "id": "9c02de", "type": "upcoming_events", "data": { "title": "Volgende quizzen", "limit": 4, "event_type": "event" } },
  { "id": "51aa07", "type": "rich_text", "data": { "html": "<p>…</p>" } }
]
```

`id` is a random 6-hex string minted when the block is added; it only
serves as a stable key in the admin form and as an anchor (`#b-9c02de`).
Every translation has its own list; nothing is shared between locales
except the page identity. (An editor creating a French translation can
start from a copy of the Dutch blocks: "Kopieer uit Nederlands" button.)

### Registry

`App\Cms\Blocks\BlockRegistry` is a container singleton built from
`config('cms.blocks')` (`type => class`). Each class extends
`App\Cms\Blocks\BlockType`:

```php
abstract class BlockType
{
    abstract public function type(): string;          // 'hero'
    abstract public function label(): string;         // admin label (Dutch)
    abstract public function rules(): array;          // validation rules, keys relative to data
    public function htmlFields(): array { return []; } // fields run through HtmlSanitizer on save
    public function assetFields(): array { return []; } // fields holding assets.id (validated exists + same org)
    public function defaults(): array { return []; }  // data for a freshly added block
    public function prepare(array $data, BlockContext $ctx): array { return $data; } // resolve assets, run queries
    public function view(): string { return 'cms.blocks.' . $this->type(); }
    public function formView(): string { return 'admin.cms.blocks.' . $this->type(); }
}
```

`BlockContext` carries the organisation, locale, the page translation and
the request; `prepare()` is where `upcoming_events` runs its query and
where `image_id` becomes an `Asset` (or `null` when deleted).

### Block types (v1) and their data

Every string field is plain text unless listed under "html". URLs go
through the `App\Rules\SafeUrl` rule: `http(s)://…`, `mailto:`, `tel:`,
or a path starting with `/` or `#`. Nothing else, so `javascript:` and
`data:` never reach a `href`.

| type | fields | html | assets | purpose (WordPress page it serves) |
|---|---|---|---|---|
| `hero` | `title`, `subtitle`, `image_id`, `buttons[] {label, url, style}` (max 3), `align` (`left|center`) | | `image_id` | every page banner; the home hero |
| `rich_text` | `html` | `html` | | free text; the imported Elementor text lands here |
| `text_image` | `title`, `html`, `image_id`, `image_position` (`left|right`), `button {label,url}` | `html` | `image_id` | over-ons, quizzen-op-maat sections |
| `cards` | `title`, `intro`, `columns` (2–4), `items[] {title, text, icon, image_id, url}` (max 12) | | `items.*.image_id` | quizpakketten, quizzen-op-maat formulas |
| `logo_grid` | `title`, `items[] {name, image_id, url}` (max 40) | | | onze-partners, in-de-pers |
| `reviews` | `title`, `items[] {quote, author, source, url}` (max 30) | | | recensies, home |
| `cta` | `title`, `text`, `buttons[] {label,url,style}` (max 2), `background` (`light|dark|primary`) | | | contact strips (`mailto:hallo@quizfabriek.be`, `tel:`) |
| `video` | `title`, `youtube_url`, `caption` | | | livestream-quizzen |
| `upcoming_events` | `title`, `intro`, `limit` (1–12), `event_type` (`event|package|all`), `show_sold_out` (bool), `empty_text` | | | evenementen, home, quizpakketten (`Event::TYPE_PACKAGE`) |
| `latest_posts` | `title`, `limit` (1–6) | | | home; replaces the RSS block |
| `faq` | `title`, `items[] {question, answer}` | `items.*.answer` | | quizzen-op-maat |

`upcoming_events` renders through the existing
`resources/views/blocks/eventtable.blade.php` markup (query:
`organisation()->events()->upcoming()->published()->orderByStartDate()`
filtered by `event_type`, exactly what `EventController@calendar` does),
so the events page is live instead of hand-maintained links.

### Rendering

`resources/views/cms/page.blade.php` extends `layouts/home` (the layout
without the page banner, since the hero block is the banner):

```blade
@foreach($blocks as $block)
    @include($block['view'], ['data' => $block['data'], 'block' => $block])
@endforeach
```

`App\Cms\BlockRenderer::render(PageTranslation, BlockContext): array`
walks the JSON, skips (and logs once) unknown types so an old page never
breaks after a block is removed from the registry, calls `prepare()` and
returns view + data per block. Views escape with `{{ }}` everywhere except
the fields the block type declares in `htmlFields()`, which are already
sanitised and are printed with `{!! !!}` inside `<div class="cms-prose">`.

Layouts get a `@stack('head')` in `layouts/blocks/head.blade.php` for
canonical, hreflang and Open Graph tags, and a `@yield('description')`
already exists in `layouts/blocks/seo.blade.php`.

### Admin form

Server-rendered, one form per translation, no framework:

- `resources/views/admin/cms/pages/edit.blade.php`: page fields (parent,
  sort order, show in menu), locale tabs (existing translations, plus
  "Vertaling toevoegen" for missing ones), and the translation form:
  slug, title, meta title, meta description, OG image, published, blocks.
- Blocks are rendered with `admin.cms.blocks.{type}` partials, fields named
  `blocks[{i}][type]`, `blocks[{i}][id]`, `blocks[{i}][data][…]`,
  repeaters as `blocks[{i}][data][items][{j}][…]`.
- `resources/assets/js/cms-editor.js` (vanilla, compiled into
  `public/js/admin.js` by `webpack.mix.js`): a `<select>` of block types
  and an "add" button that clones the `<template data-block-type="…">` for
  it, remove / move up / move down buttons, and re-indexing of `name`
  attributes on every change. Same for repeater rows. Nothing is posted by
  JS; the form submits normally with CSRF (`{{ csrf_field() }}`), the
  `VerifyCsrfToken` middleware being back on since the 2026-08-27 audit.
- Validation in `App\Cms\BlockValidator::rules(array $blocks): array`:
  first `blocks.*.type` must be a registered type and `blocks.*.id` a
  6-hex string, then, per index, the type's `rules()` prefixed with
  `blocks.{i}.data.`; asset fields get `exists:assets,id`; max 40 blocks.
  Errors are shown at the top of the form (the `$errors->all()` pattern of
  `admin/guests/index.blade.php`) and next to the block.
- On save, `htmlFields()` are sanitised, unknown keys dropped (only the
  keys the type's `rules()` mention are kept), and the translation stored.
  Saving also forgets the sitemap cache.

### Rich text editor

**TinyMCE 6 (MIT), self-hosted from npm** (`tinymce` package, copied to
`public/js/tinymce` by `webpack.mix.js`; no API key, no CDN, no telemetry).
Reasons over Trix: headings, lists, links, images with alt text, tables
and YouTube embeds are all in the imported Gutenberg content; Trix only
does one heading level and no tables. TinyMCE 7 is GPL-2+, which this
GPL-3 project could also use, but 6.x is pinned to avoid the licence
question altogether. Configuration lives in `cms-editor.js`:

- `plugins: link image lists table media code`, `menubar: false`,
  `valid_elements` mirroring the server allow-list (client-side comfort
  only, the server sanitiser is the authority),
- `images_upload_url: /admin/cms/upload` with the CSRF header from
  `<meta name="csrf-token">`, `automatic_uploads: true`,
- `media` restricted to YouTube (`media_url_resolver` rewriting to
  `youtube-nocookie.com`),
- `content_css: /css/app.css` so the editor looks like the site.

### HTML sanitisation

`App\Cms\HtmlSanitizer` wraps **`symfony/html-sanitizer`** (already the
Symfony ecosystem Laravel 12 runs on, PHP 8.2+, no cache directory,
WHATWG-style allow-lists). It is used on every write path: the admin
forms, the import command, and nowhere else is HTML accepted.

Allow-list (`config/cms.php` → `sanitizer`):

- Elements: `p br h2 h3 h4 strong b em i u s a ul ol li blockquote pre
  code hr img figure figcaption table thead tbody tr th td iframe span div`.
  `h1` is demoted to `h2` (the page title is the H1).
- Attributes: `a[href title target]`, `img[src alt width height loading]`,
  `iframe[src width height allow allowfullscreen title]`,
  `td/th[colspan rowspan]`, `class` everywhere but filtered to the
  `wp-block-*`, `align*`, `has-text-align-*`, `cms-*` prefixes (needed for
  the imported Gutenberg galleries and alignment).
- No `style`, `id`, `on*`, `srcset` (the import rewrites images anyway).
- Links: `allowedLinkSchemes = [http, https, mailto, tel]`,
  `allowRelativeLinks`, `forceHttpsUrls` off (mailto/tel), `target=_blank`
  gets `rel="noopener noreferrer"`.
- Media: `allowedMediaSchemes = [https]`, `allowedMediaHosts` = the central
  storage front host (`config('centralstorage.front')` / `CENTRALSTORAGE_FRONT`),
  `www.youtube-nocookie.com`, `www.youtube.com`, `player.vimeo.com`.
  So an `<iframe>` survives only when it points at those hosts and an
  `<img>` only when it is one of our assets (or an absolute https image
  the editor pasted; open question 6).
- Max input length 2 MB; the result is what gets stored.

Only a sanitised field is ever printed with `{!! !!}`, and only inside the
block/post views. `organisations.footer_html` (printed raw in
`layouts/blocks/footer.blade.php:110`) predates this and is out of scope,
noted below.

## Media

- Block images and post featured images are `assets.id` references to
  rows created by `\CentralStorage::store(UploadedFile)`, the same call
  `Admin\AssetController@upload` makes. Rendering uses
  `$asset->getUrl(['width' => 1280])` etc., as `series/view.blade.php` and
  `layouts/front.blade.php` do today.
- New admin endpoints, both `auth` + `admin`:
  `POST admin/cms/upload` (TinyMCE and the block image pickers; validates
  `image|max:10240`, returns `{ "id": 42, "location": "<url>" }`) and
  `GET admin/cms/assets?q=` (JSON list of the organisation's recent images
  for the picker; `assets.user_id` is the only ownership we have, so the
  list is "uploaded by admins of this organisation", see open question 5).
- Inline images in rich text are stored as absolute central-storage URLs
  inside the HTML (there is no reference table; deleting an asset that a
  post uses is the admin's problem, as it is for series headers today).
- Import: every `wp-content/uploads/...` URL referenced by a post body, a
  gallery or `featured_media` is downloaded once (original size: the
  `-WxH` suffix is stripped and the original tried first, falling back to
  the sized file), stored through central storage, and the body rewritten
  to the new URL. A `cms_redirects` row maps the old upload URL to the new
  asset URL so image search results keep resolving.
- A short `cms.scss` (imported by `app.scss`) styles `.cms-prose`
  and the surviving Gutenberg classes: `wp-block-image`,
  `wp-block-gallery` (grid), `wp-block-embed` (16:9), `alignwide`,
  `has-text-align-center`, `figcaption`.

## Admin UX

Sidebar in `resources/views/layouts/admin.blade.php` gets a "Website"
section: Pages, Posts, Redirects. Copy is Dutch like the guest/refund
screens.

- **Pages index** (`/admin/pages`): tree ordered by `sort_order`, one row
  per page with its Dutch title (or the first available), a badge per
  locale (`nl` green = published, grey = draft, missing = "+"), the public
  path, "Bekijk" (preview), "Bewerk". "Nieuwe pagina" creates the page and
  its Dutch translation in one form.
- **Page edit** (`/admin/pages/{page}/edit/{locale}`): as described under
  Admin form. Actions: save, save & preview (`?preview=1` on the public
  URL), publish / unpublish, delete translation, delete page (only when
  it has no children). The page chosen as `organisations.home_page_id` shows a
  "Startpagina" badge; the index has a "Stel in als startpagina" action
  and the organisation edit form a "Startpagina" select (both write
  `home_page_id`). The home page cannot be deleted while it is selected.
- **Posts index** (`/admin/posts`): newest first, title, date, locale
  badges, published state. **Post edit** (`/admin/posts/{post}/edit/{locale}`):
  published date, featured image, and per locale slug, title, excerpt,
  body (TinyMCE), meta, published.
- **Redirects** (`/admin/redirects`): table + add/delete form; the import
  fills it, editors add entries when they rename a slug (the page edit
  form offers "Maak een redirect van het oude adres" when a published
  slug changes, pre-filled).
- Authorization: routes sit in the existing `auth` + `admin` group of
  `routes/web.php`; every controller resolves the record through the
  acting admin's `getActiveOrganisation()` and requires
  `$organisation->isAdmin($user)`, the pattern of
  `GuestRegistrationController::getEventInOrganisation()`. `PagePolicy`
  and `PostPolicy` are registered in `AuthServiceProvider::$policies` for
  consistency with the other models, and the controllers call
  `$this->authorize()`.
- The page and post editors are **custom controllers**
  (`Admin\PageController`, `Admin\PostController`) because the block
  editor UI (repeaters, TinyMCE, image picker) does not fit
  `FrontCrudController`'s generated forms. They do **not** own any write
  logic: both they and the Charon API (next section) call the same
  `App\Cms\PageWriter` / `App\Cms\PostWriter` services, so validation,
  sanitisation, path rebuilding and cache busting are identical on every
  write path. Redirects are a flat resource, so their admin screen is a
  normal Charon `Admin\RedirectController` (`::routes('cmsRedirects', ...)`)
  on top of the API resource (decided with the API requirement; closes open
  question 7).

## Charon API

Decided: all CMS content is editable through the Charon API
(`app/Http/Api/V1`), with the same resources, validation and
authorisation as the admin. Registered in `app/Http/Api/V1/routes.php`
next to the existing controllers, so they appear in the Swagger
description (`/docs`) automatically.

| Resource | Route (`/api/v1/...`) | Controller pattern |
|---|---|---|
| Pages | `organisations/{organisation}/pages` | `ChildCrudController`, like `SeriesController` |
| Page translations | `pages/{page}/translations` | `ChildCrudController`, like `Events\TicketCategoryController` |
| Posts | `organisations/{organisation}/posts` | `ChildCrudController` |
| Post translations | `posts/{post}/translations` | `ChildCrudController` |
| Redirects | `organisations/{organisation}/cmsRedirects` | `ChildCrudController` |
| Home page | `home_page_id` on the existing `OrganisationResourceDefinition` (writeable, must be a page of the same organisation) | existing |

- **Resource definitions** in `app/Http/Api/V1/ResourceDefinitions/Cms/`:
  `PageResourceDefinition` (parent, sort_order, show_in_menu, and a
  visible `translations` relationship, expandable), 
  `PageTranslationResourceDefinition` (locale, slug, path read-only, title,
  meta, og image, is_published, published_at read-only, `blocks`),
  `PostResourceDefinition`, `PostTranslationResourceDefinition` (body
  instead of blocks), `CmsRedirectResourceDefinition`. The translation
  URL (`getUrl()`) is exposed read-only as `url`.
- **`blocks` over the API** is the same JSON list that is stored
  (`[{"type": "...", "data": {...}}]`). Charon has no nested-object field
  type, so the field is declared as a string carrying JSON and decoded in
  the controller's `beforeSaveEntity()`; if the installed Charon version
  supports an `object`/`array` field with raw JSON in and out, use that
  instead (verify in `vendor/catlabinteractive/charon` during Task 2.4).
  Either way the payload goes through `BlockValidator` and the sanitiser
  inside `PageWriter`; a validation error is thrown as a Charon
  `ResourceValidationException` so API clients get the standard 422 shape.
- **Authorisation**: the API group already requires `auth`
  (`routes.php`, the OAuth `full` scope). `PagePolicy`, `PostPolicy` and
  `CmsRedirectPolicy` implement `index/create/view/edit/destroy` like
  `SeriesPolicy` (organisation admin only), and Charon calls them through
  the existing `ResourceController` base. Reading unpublished content
  through the API is admin-only as well; the public site never uses the
  API.
- **Assets**: images referenced by `image_id` / `og_image_id` are uploaded
  through the existing asset flow; if the API has no asset upload
  endpoint yet, add `POST organisations/{organisation}/assets`
  (multipart, same validation as the admin upload) so an API client can
  create a page with images end to end.
- **Tests**: `tests/Integration/Cms/Api/*` create, update, publish and
  delete pages, translations, posts and redirects through `/api/v1/...`
  as an organisation admin; a non-admin and an admin of another
  organisation get 403/404; invalid blocks and a `<script>` in rich text
  return 422 / are stripped; `home_page_id` pointing at another
  organisation's page is rejected.

## WordPress import

`php artisan wordpress:import {--site=https://www.quizfabriek.be} {--organisation=ID} {--posts} {--pages} {--redirects} {--dry-run}`
in `app/Console/Commands/WordPressImport.php`, with the HTTP and mapping
logic in `App\Cms\Import\WordPressImporter` so it is testable with
`Http::fake()`.

- **Posts**: page through `/wp-json/wp/v2/posts?per_page=100&page=N&_embed=1`.
  Map `slug`, `date` (site-local, Europe/Brussels → `published_at`),
  `title.rendered` (HTML entities decoded), `excerpt.rendered` (tags
  stripped, `[…]` removed), `content.rendered` → media rewrite → sanitise
  → `body`, `featured_media` via `_embedded['wp:featuredmedia'][0].source_url`.
  Locale `nl`, `is_published = status === 'publish'`. Upsert on
  `(organisation_id, wp_post_id)`; a re-run updates the body and never
  duplicates.
- **Pages**: page through `/wp-json/wp/v2/pages`, skip slugs ending in
  `-nieuw` and `sko_milk` (`--skip=` option, defaults from the assessment),
  reproduce the parent hierarchy, and store `content.rendered` (Elementor
  HTML, sanitised, which flattens it to headings/paragraphs/images) as a
  single `rich_text` block in an **unpublished** Dutch translation. This is
  raw material for editors, not a port: the real pages are rebuilt from
  blocks in the admin before cutover. The WordPress home page is imported like any other page
  (the `front page` setting is not public, so `--home=<slug>` names it);
  with `--home`, the command sets `organisations.home_page_id` to it.
- **Redirects**: read `/post-sitemap.xml` and `/page-sitemap.xml`, and for
  every URL that does not resolve to an imported page/post path print it,
  so the remaining map (`/category/…`, `/feed/`, `/author/…`) can be
  filled by hand. Media redirects are written automatically.
- Network access only to `--site`; nothing else is fetched (no SSRF
  surface beyond the operator's own argument). Idempotent, `--dry-run`
  prints the mapping without writing.
- Runs against production with WordPress still live, before DNS moves.

## Redirects

- Page slugs are kept identical to WordPress, so pages need no redirects
  by default. The old `/YYYY/MM/DD/slug/` post URLs are the new URLs.
- `cms_redirects` covers: media (`wp-content/uploads/…` → asset URL,
  written by the import), taxonomies and feeds (hand-entered), renamed
  slugs (offered by the page form), and `?p=ID` shortlinks (resolved by
  `wp_post_id`, no table row needed).
- Resolution order for a miss in `PageController@show` and in the
  fallback route: exact `from_path` match for the organisation → 301/302
  with the query string appended → otherwise 404.
- `tickets.quizfabriek.be → quizfabriek.be` is a domain-level redirect
  (Cutover), not a row.
- WordPress-only paths that should die (`wp-login.php`, `xmlrpc.php`,
  `wp-admin`, `wp-json`) get an explicit 410 list in `config('cms.gone')`
  handled by the fallback route, so bots stop hammering them and Errbit
  does not fill up with 404 noise (404s are not reported anyway,
  `Handler::$dontReport`).

## SEO, sitemap, hreflang

- `<title>`: `meta_title ?: title` + ` – {organisation name}` (the
  `head.blade.php` pattern). `<meta name="description">` from
  `meta_description`, else the post excerpt, else the first 160 chars of
  the first text block. The existing hard-coded Quizfabriek default in
  `seo.blade.php` remains the last fallback.
- `<link rel="canonical">`: absolute, locale-prefixed, no trailing slash,
  built from `request()->root()` (which `AppServiceProvider` derives from
  the forwarded host).
- `hreflang`: one `<link rel="alternate" hreflang="{locale}">` per
  **published** translation of the same page/post, plus
  `hreflang="x-default"` pointing at the Dutch one. Rendered by a shared
  `resources/views/cms/partials/alternates.blade.php` pushed onto the
  `head` stack.
- Open Graph: `og:title`, `og:description`, `og:image` (OG image, else
  hero image, else featured image, else the existing default), `og:type`
  `article` for posts with `article:published_time`.
- JSON-LD: `BlogPosting` for posts (headline, datePublished,
  dateModified, image, publisher = organisation), `WebPage` for pages,
  through the existing `@yield('jsonld-content')`.
- Language switcher in `layouts/blocks/navigation.blade.php`: only shown
  when the current page/post has more than one published translation,
  listing exactly those. Ticketing pages show none.
- **Sitemap**: `SitemapController::buildUrls()` appends every published
  page translation and post translation of the organisation
  (`lastmod = updated_at`, pages priority 0.8 / weekly, posts 0.5 /
  monthly, the blog index 0.6 / weekly). Each `<url>` also emits
  `<xhtml:link rel="alternate" hreflang>` entries (view gains the
  `xmlns:xhtml` namespace). The cache key becomes
  `laravel.sitemap:{organisation_id}` (today's single key serves the first
  host's sitemap to every domain, see open question 9), and saving a page
  or post forgets it.
- `robots.txt` stays `Allow: /`; drafts are never linked and previews are
  `noindex`.

## Caching

- No page cache. A CMS page costs one translation query, one parent chain
  (menu), plus whatever `upcoming_events` / `latest_posts` run — the same
  order of work as the series page.
- `latest_posts` and the navigation menu (pages with `show_in_menu` per
  locale) are `Cache::remember`ed for 5 minutes under keys that include
  the organisation id and locale; page/post saves forget them (model
  observers in `App\Cms\CmsCacheObserver`).
- Sitemap: existing 1-hour cache, per organisation.
- Route cache: compatible (see Routing).
- The static `Organisation::getRepresentedOrganisation()` memo is per PHP
  process, which is fine under Apache prefork but must be resettable in
  tests (see Testing).

## Cutover and rollout

Shipped in phases (details in the plan). Content work happens on
production between phases, with WordPress still serving `quizfabriek.be`.

1. **Foundation** (schema, models, sanitiser, block registry, locale
   middleware, public routes, page rendering). Invisible: no organisation
   has pages yet.
2. **Admin editor** for pages. Editors can start building on
   `tickets.quizfabriek.be/admin/pages`, previewing drafts.
3. **Posts**: model, admin, blog routes, `latest_posts` block, and the RSS
   block in `series/view.blade.php` replaced.
4. **Import** command; run it on production. Editors rebuild the nine
   pages from the imported text, publish them as drafts-in-preview.
5. **SEO plumbing**: sitemap, hreflang, switcher, redirects admin,
   canonical-domain middleware, `cms` lang files.
6. **Cutover** (an afternoon, reversible by DNS):
   - Add `quizfabriek.be` and `www.quizfabriek.be` as `OrganisationDomain`
     rows for Quizfabriek; mark `www.quizfabriek.be` `is_canonical` (decided).
   - Add both to `VALID_DOMAINS` (only consulted by the no-op middleware,
     but keep it consistent) and to the TLS certificate.
   - Publish the Dutch home page and select it as the organisation's
     "Startpagina", so `/` switches from the series page to the CMS home for
     this organisation only.
   - Point DNS at the Laravel host. `tickets.quizfabriek.be` starts
     301-ing to the canonical domain with the same path through the new
     `CanonicalDomain` middleware; the cookie-consent cross-domain list in
     `head.blade.php` already includes `quizfabriek.be`.
   - Verify: home, the nine pages, three posts, `/sitemap.xml`, an old
     upload URL, `/events`, a ticket purchase, `/admin`. Submit the sitemap
     in Search Console for the new property.
   - Keep WordPress reachable on an internal hostname for two weeks for
     reference, then shut it down and cancel Elementor Pro.
   - Rollback: DNS back to WordPress; nothing in Laravel depends on the
     domain.

## Risks

- **Editors rebuild nine pages by hand.** The import gives them text and
  images, not layout. Budget a content day after phase 4 and review the
  pages on a phone; the block set is deliberately small, so ask for a new
  block type rather than abusing `rich_text`.
- **The RSS block was already broken** (`Feeds` class missing); replacing
  it is safe but confirm `blog_rss_url` is `NULL` on production before
  assuming the homepage renders today.
- **`getRepresentedOrganisation()` is memoised per process from
  `$_SERVER['HTTP_HOST']`**, not from the request. Fine in production; in
  tests it needs the reset helper, and any future queue job rendering
  pages must pass the organisation explicitly.
- **Central storage is external.** Import of ~100 media files depends on
  it being up; the command retries and is idempotent.
- **Sanitiser strictness vs. imported content.** Elementor HTML will lose
  its structure (intended) and Gutenberg posts may lose the odd embed
  (Facebook, Twitter). The import prints a diff of dropped elements per
  post so they can be checked.
- **Route precedence drift.** A future ticketing route added after the CMS
  group would be shadowed by the catch-all; the reserved-slug test plus a
  comment at the bottom of `routes/web.php` guard against it.
- **`route:cache` and the `{locale}` group**: verified by running
  `artisan route:cache` in the test job (`.github/workflows/tests.yml`).
